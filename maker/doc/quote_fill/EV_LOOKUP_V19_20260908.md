# EV lookup v19：五項修正與驗證

範圍：`maker/src/ev_lookup`，研究端，保留 1 Hz 策略決策。
原 v18 主程式／決策依賴存於 `archive_v18/`；原始資料、canonical、S0、taker 程式未修改。
本次沒有券商下單、部署或 commit。

**原 v17 的 20M、27,950 元／日是 S1 現貨 maker + S2 期貨 maker 合計。
該數字含已確認的 lookahead 與執行偏差，不能當作可實現績效。**
原版逐項證據與重現數字見 [稽核報告](EV_LOOKUP_AUDIT_20260908.md)。

## 1. bpday 與 EV

`causal_lookup.py` 的開盤快照不可修改：只取前 20 個已完成 session 解決的 shadow 結果，
並再次要求 `available_ns < D 日開盤`。當天 carry 退出、同日交易退出及到期入帳均不會改動當天查表。
P_sd 要等進場日結束才更新；lambda 僅取前五個完成日的容量拒絕機會。
同日資料先在回放中成為已觀測事件，再於下一 session 凍結成表，沒有預先更新當天決策。

查表的 basis 桶改用**掛單時 basis**。`decide.py` 只在送單前執行 positive basis / EV / bpday / cap。
不再將未来 maker 成交價差或 hedge 後的損益條件放進准入特徵。
表的來源是無容量限制、使用相同成交量與 hedge 規則的 shadow 回放。

所以 **EV + 前日 bpday 可以日內實做**：每秒拿當下報價及昨日前已知統計決定是否掛單。
它是依已知資訊篩選，沒有辦法先知道未來哪一筆最賺，也尚未證明相較 EV / FCFS 有穩定優勢。

## 2. carry 與硬容量

完全移除 `expected_overnight` 和預先剔除當日將退出 carry 的路徑。
容量由整數 cents 帳本管理：

`pending reservation + 未 hedge 成交 + 日內 paired + carry <= CAP`

S1 現貨限價買單按限價名目預留；S2 期貨賣單按現貨當日公布漲停價預留現貨 hedge 額度。
hedge 完成後縮成實際現貨買進名目；撤單生效／部位兩腿完成才釋放。
P_sd 只影響 EV，不會把某個預計當沖的部位折算成較少容量。

這裡 CAP 是現貨腿進場名目加 pending，並非兩腿名目合計、保證金或當日市值上限。
新主線沒有加單商品 10M 限制。

**只在成交時看上限，無法保證雙 maker 實盤硬限制。**
兩路在外委託可能於撤單生效前一起成交，因此 v19 讓兩路共用預留。
這會降低可以同時掛出的廣度，是實作硬限制的真實成本。
成交按實際 receive timestamp 處理；同一 timestamp 的公共成交先於撤單、新掛單。
同秒新倉仍有固定 tie convention（S1 指令先於 S2、S2 按商品碼），不能說這等於市場真實微觀先後。

另抓到 2026-07-24 的 6182：`allow_day_trade_mark=N`，已退出當天新倉名單，
但之前的 `PLFH6` 部位和期貨交易仍存在。v19 額外載入既有持倉的精確合約及當日參考資料，
不能因為不再符合新倉資格而消失或切換到其他月份。
原研究 85 個日期的逐日期貨基本資料已用既有唯讀 loader 補成獨立快取。

## 3. 不再刪除不利成交

S2 期貨 maker 成交後，必須處理現貨 buy hedge；S1 現貨 maker 成交後，必須處理期貨 sell hedge。
時間從 maker 的實際逐筆 timestamp 加 50ms 起算，使用當時可見且可執行的五檔價格和數量。
例如掛單時是正 basis，50ms 後現貨 A1 已漲過期貨成交價，部位仍成立，負 basis 照留。
沒有第二次 EV / bpday / positive-basis gate 可以把成交報告刪掉。

必要 hedge 不受進場的 -9%/+8% 篩選緩衝阻擋；現貨使用每日公布漲跌停，標準股票期貨使用參考價上下 10%。
後者依據 [期交所股票期貨規格](https://www.taifex.com.tw/cht/2/sTF)。
五檔不夠時保留未 hedge 風險與容量、等待後續有效盤口，五秒後明確記 timeout；不以缺價為理由消除部位。
S1 若只買到部分股數便撤單，不能虛構一個分數期貨合約：已買現貨另行 taker 賣回並記損益。

## 4. 出場

原做法先掃整天，跳過事後無 makerFill 標籤的 touch，又把 `effU + 5 - cost` 當作已實現收益。
v19 不再讀任何出場 makerFill 標籤：

1. 首次出現因果出場條件時掛現貨 Ask，保存自己的固定賣價。
2. 每秒以當時 Future Ask 核對這個固定賣價能否維持凍結目標；條件失效或盤口無效即撤單。
3. 原始正式成交量依價位／FIFO 分配，前方數量和自己的每筆數量一起扣；穿價不產生無限成交量。
4. 現貨全數賣完後，50ms 起按當時 Future Ask／五檔實際買回。
5. 所有數量平衡後才計算四腿現金流、20／34bp 成本並釋放容量。

第 2 步是新增的明確出場維護規則。單純把「第一次觸價」掛單一直留到成交，
會在期貨 hedge 變差後仍賣出現貨；初步回放已出現大額損失。
此修正只能取消尚未成交的掛單：若成交先於撤單生效，仍須 hedge 並承受損失。
13:18 撤剩餘 maker 單；部分現貨退出需補完剩餘現貨及期貨，未動到的完整 pair 留倉。

原 8039／7 月 24 日案例已做成真實資料回歸：前面 37 張、自己 40 張，
到原版聲稱全平的 09:12:47 只有 41 張符合價格的公開成交。
新分配器只給自己 4 張（兩口期貨對應股數），不會把 20 口都標為完成。

到期綁原 `QuoteCode` 的 `end_date`，不再用嚴格 `>` 的下一月份日期。
保留 C8「到期後下一 session 兩腿同價、basis=0」會計慣例，輸出明確標成
`expiry_basis_zero_accounting`；它仍不是實際現貨與期貨結算成交證明。

## 5. 驗證範圍與結果

行為回歸共 **21 項通過**，涵蓋 future-outcome perturbation、快照不可變、20-session 窗口、
carry 與 pending 共用上限、負 basis 必做 hedge、部分成交回滾、退出第二腿時序、
錯月份成交排除、到期次 session 入帳、進場資格消失但持倉保留、撤單競態與真實 8039 成交量。

三段獨立完整商品日回放（每段從空倉／空表起跑）：

- 2026-05-19、20、21：月到期前後。
- 2026-07-20、21、22、23、24、27：連續六個 session；同時比較 EV + bpday、EV、FCFS。
- 2026-08-18、19、20：從 raw 重建 extension 1 Hz 格，加上另一次月到期；此段只有 S2。

同一套 raw book、成交量分配、成本及硬容量用於各政策。另重放 5 月三日、撤單延遲 50ms 的敏感度。
`verify_run.py` 從輸出重新核對四腿金額、兩腿數量、容量 release 時間、前日 cell 統計與 source hash；
指定日期另直接回查 NAS 期貨／SSD 現貨逐筆，確認原合約價格和每筆公共成交量足夠支持自己分配的數量。

例如 7/27 結束時，EV + bpday 的 carry 名目為 12,495,300 元；在次日任何退出實際完成之前，
20M 帳本只有 **7,504,700 元**可供新 pending 預留，不會因為提前知道誰將退出而多給額度。
三段基準 EV + bpday 合計保留 50 筆 hedge 後非正 basis，沒有在成交後刪掉它們。

所有受限帳本的峰值（包括 pending）不超過 20,000,000 元。
所測受限帳本每天收盤 `unhedged=0`；shadow 在 7/21 留下一筆未 hedge，7/22 才完成，未被抹除。
撤單延遲版本的收益不是單調下降：它也改變成交集合、後續容量和前日統計，不能把單一短段差額當作 latency 成本估計。

四組 `verification.json` 均為 `passed=true`。含 shadow、政策對照及延遲對照，
共核驗 42 個 portfolio-day、5,295 次 maker 部分／完整成交事件；
其中 1,937 個 portfolio 內的 print 聚合另外核對原始成交量與原合約價格。
不同 portfolio 可以重放同一個市場 print，這不是 1,937 筆獨立市場樣本。

## 6. 能得出與不能得出的結論

這五條程式路徑已改成因果、會保留不利成交、並在所選回放下確實限制容量。
本 v19 報告原先只完成短段驗證。**後續完整期間已重跑，含原 85 個行情日及 8/28 資料中斷 session，
結果與容量比較見 [v20 完整報告](EV_LOOKUP_V20_FULL_20260908.md)。原 27,950 元／日不再適用。**

v19 的成交規則是明確的公開逐筆量守恆近似：不把外部撤單直接兌換成自己的排隊優先權，
不把單純 book cross 當成新增成交量，可能少填／晚填；不是交易所真實我方撮合，也不是保證的損益下界。
S1 原 approximate entry 也已改成共享數量與部分成交，因此新舊差距不能全部歸因於移除 lookahead。

v19 短段期末仍可能有 carry，當時的 daily 是已實現損益；後續 v20 另列期末估值、融資敏感度及公司行動事前風控。
shadow 曾出現 hedge timeout／跨日未 hedge，這些未被刪掉；各 20M 帳本的相應統計見逐日結果。
目前不能承諾「市場熱度差不多，研究與實盤差異就不大」，也不能僅依短段已實現損益宣稱 bpday 政策勝出。
