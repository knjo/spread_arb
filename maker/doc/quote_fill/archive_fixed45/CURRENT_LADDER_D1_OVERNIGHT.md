# Current-ladder D+1 fresh-1s overnight benchmark

`current_ladder_overnight.py` is a source-bound orchestration layer over the
existing `overnight_carry_runner.py` and `overnight_carry_report.py`. It does
not replace either producer or change their label/report arithmetic.

> Universe caveat: the 45 products are inherited from the retrospective
> `first_wave_45` research cohort, whose membership uses realized May–Aug
> outcomes. Immutable inheritance proves lineage, not D-safe selection; this
> benchmark is conditional on that cohort and is not a deployable allowlist.

The fixed policy is:

- start only from strict same-day carry branches already produced by the
  current `exit_maker_narrow_60d` root;
- inspect exactly the next session in the prerequisite observation calendar;
- retain the entry `QuoteCode` and never substitute a roll;
- cross the first jointly executable spot bid and futures ask;
- require each book age to be at most 1,000,000,000 ns, inclusively;
- use zero added exit latency and no settlement-price imputation.

The 60 entry dates, 45 products and 2,687 available product-day keys are
derived from the immutable entry and same-day root manifests. The full
60 x 45 grid is retained in `gap3_product_day_universe.parquet`, including the
13 unavailable cells. The 135-session prerequisite calendar is used only to
map each entry date to D+1; it is never sliced with `[-60:]` to choose entries.

Preflight rebuilds every entry and same-day partition row with the existing
producer verifiers, validates declared artifact hashes, requires the physical
`Date=*/ValueCode=*` trees to equal the 2,687 manifest keys, and compares the
three inventories above to fixed contract anchors. These are not trust-on-first-
use hashes generated by the replay.

The formal wrapper also fixes the canonical spot raw root to `HFT_DATA_ROOT`
and the futures raw root to `DEFAULT_FUTURES_RAW_ROOT`; the CLI exposes no raw-
root override. The public verifier recomputes each D+1 candidate's path, byte
size and `mtime_ns` and requires exact equality with every partition config.
This detects stat drift but intentionally remains weaker than a content SHA.

## Formal 60-session result

The formal root is
[`overnight_carry_narrow_60d_d1_fresh1s_current_ladder`](../../data/walkforward/overnight_carry_narrow_60d_d1_fresh1s_current_ladder).
It contains all 2,687 available product-days from the 60 x 45 grid and produces
54,188 strict policy-alternative labels. Deduplicating aliases leaves 17,803
physical entry dependencies:

| Physical D+1 outcome | Rows | Share |
|---|---:|---:|
| First jointly executable fresh-book exit priced | 16,953 | 95.226% |
| Expiry settlement unavailable, kept censored | 549 | 3.084% |
| No jointly executable spot-bid/future-ask book within 1 s | 301 | 1.691% |

The policy-label priced rate is 51,837 / 54,188 = 95.661%; it differs from the
physical rate because one physical dependency can have several non-independent
policy aliases.

For the 16,953 priced physical exits, gross cashflow before every omitted cost
is **-5,352,850 TWD**. Per physical dependency, gross return has mean
**-11.412 bp**, median **-11.751 bp**, p05 **-85.714 bp**, p95 **56.818 bp**,
and positive/zero/negative rates of 33.227% / 13.248% / 53.525%. The
notional-weighted result is **-9.530 bp** on
5.617 billion TWD of normalization notional. Split only by entry route,
`future_ask_spot_taker` has an unweighted physical mean of -19.130 bp over
7,245 priced entries; `spot_bid_future_taker` has -5.652 bp over 9,708.

The median holding time is 80,651 seconds (22.40 hours) and p95 is 258,132
seconds (71.70 hours, including weekends). The selected D+1 books satisfy the
inclusive 1 s freshness contract: spot/future age p50 is 0.538/0.000 ms, p95 is
247.843/162.099 ms, and observed maxima are 975.141/974.223 ms.

These are counterfactual facts across the full strict-carry diagnostic cohort,
not an allocated portfolio. The daily median is 274 physical dependencies and
92.36 million TWD of priced normalization notional; the maxima are 1,033 and
250.41 million TWD. Those figures must not be read as the q95 challenger's
required capital or turnover. This report deliberately has no boundary-q field,
joint visible-volume allocation, partial-inventory path, fee/tax/financing cost,
or marked NAV. Policy rows also cannot be summed across q/rule/route.

Boundary q is not a formal report column. A separate diagnostic parses q from
all 54,188 `entry_policy_generation_id` values; its physical cohorts overlap,
so this is not a causal or additive best-q comparison:

| Derived q | Physical support / priced | Notional-weighted gross | Positive rate |
|---|---:|---:|---:|
| q50 | 13,036 / 12,436 | -11.761 bp | 30.589% |
| q80 | 7,309 / 6,946 | -8.127 bp | 35.646% |
| q95 | 2,916 / 2,778 | -3.364 bp | 40.101% |

Only two q95 + `spot_bid_future_taker` + `frozen_lower` provenance cells are
slightly positive (+1.026 and +1.782 bp), still before all costs and with zero
added D+1 exit latency. This is compatible with taking q95 to unseen shadow
testing, but is not permission to label q95 as the production optimum.

The practical conclusion is therefore narrow but strong: forcing the remaining
strict-carry population through the first fresh D+1 taker/taker close is highly
priceable, but is already negative before costs. It is an inventory-resolution
benchmark, not evidence of overnight alpha and not a production exit policy.

## Commands

Run the bounded source-only preflight:

```bash
systemd-run --user --wait --collect --pipe \
  --unit=gap3-current-ladder-preflight \
  --property=MemoryHigh=8G \
  --property=MemoryMax=12G \
  --property=MemorySwapMax=0 \
  --property=Restart=no \
  --working-directory=/home/kevin/Project/HFT/src/research/futures_spot_spread \
  uv run --no-project python -m \
    maker.src.quote_fill.current_ladder_overnight_cli --preflight-only
```

Launch or resume the formal replay using the same resource properties, but
omit `--preflight-only`. There are deliberately no CLI switches for entry
sessions, symbols, carry horizon or freshness; changing any of those values is
a different policy and must use a new version.

```bash
systemd-run --user --wait --collect --pipe \
  --unit=gap3-current-ladder-formal \
  --property=MemoryHigh=8G \
  --property=MemoryMax=12G \
  --property=MemorySwapMax=0 \
  --property=Restart=no \
  --working-directory=/home/kevin/Project/HFT/src/research/futures_spot_spread \
  uv run --no-project python -m \
    maker.src.quote_fill.current_ladder_overnight_cli
```

After completion, run the public source-rebinding verifier under the same
memory cap:
