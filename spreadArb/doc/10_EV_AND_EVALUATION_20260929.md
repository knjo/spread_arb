本次從既有交易明細補齊統計，重新核對一筆真實候選的 EV；沒有重跑行情或改動策略。

**採用狀態更新：使用者已選擇回零篩選＋max-Q 出場，以 B 動態 hurdle 為主。**
本文的『實際目標 EV』為歷史對照版本；公式例子從其封存程式重算，不隨目前預設策略改變。

## 1. EV 究竟改了什麼

目前有三種候選路線：residual（各個 anchor 相對目標）、settle（抱到結算）、absolute（原本估收斂到零）。
進場用 `score = EV / 預估持有日曆日` 排序，再比較 hurdle。
A 的 8.5 bp／交易日換算為 5.8219178 bp／日曆日；B 的動態門檻規則另依前日資金使用調整。

### 1.1 改動前：回零分數篩選，但可在 max-Q 提早出場

absolute 用回零樣本表估計「價差到 0」所需時間，算回零收益與 EV。
若這條路線分數最高且通過 hurdle，就能進場；實際出場目標卻是 `max(0, Q 目標)`。
Q 目標是 residual 候選裡 **EV／時間分數最高**的那個目標，並非取數值最大的價差。
因此原策略同時用了兩件事：回零分數作進場篩選，正值目標作提前獲利。

### 1.2 改動後：正值 Q 目標的評估取代 absolute 評估

`policy.decide_row` 先算完所有路線，找出上述 Q 目標。如果目標 > 0，
把 absolute 的 `EV、持有時間、當日／隔日到達機率、score` 全部換成該 residual 目標的評估，
再重新選最高分路線。程式實際是複製該筆 residual 評估並把 route 標成 absolute；
兩者在這一步的分數相同，absolute 不再提供一份額外的高回零分數。
若 Q 目標不存在或不大於 0，仍保留回零 absolute 評估。

這個替換同時改了三件事：

| 項目 | 原回零篩選 | 實際目標篩選 |
|---|---|---|
| 提前出場的價差空間 | 進場價差 − 0 | 進場價差 − Q 目標 |
| 到達機率來源 | absolute 回零首達時間表 | residual reach 表的 C0／C1／q |
| 持有時間 | 回零／結算時間的加權平均 | 到 Q 目標／結算時間的加權平均 |

**不是只把原 EV 減去 Q 目標**。仍有到期前未到目標、最後按 basis=0 結算的分支，且機率表也換了。
兩張表的樣本條件不同，不保證估出的正值目標到達機率一定高於回零機率；公式一致不表示已校準。

以 `b` 為進場價差、`q` 為出場目標，概念公式為：

```text
到目標且當日出場淨收益 = b − 進場滑價 − q − 出場滑價 − 20 bp
到目標且隔夜出場淨收益 = b − 進場滑價 − q − 出場滑價 − 34 bp
未到目標、持有到期淨收益 = b − 進場滑價 − 結算成本 − 適用費用
EV = 各分支機率 × 各分支淨收益，加總
T  = 各分支機率 × 該分支預估日曆時間，加總
score = EV / T
```

這是進場前的估計。交易完成後的損益仍按實際雙腿成交現金流及費用計算，不拿 EV 當已賺到的錢。

### 1.3 真實例子：2026/6/1 10:10:07，2355 S2

原交易 ID `S2/20260601/2355/4860`。進場價差 **128.2051 bp**；
anchor 96.0392、scale 18.4158，最佳 residual 的 x = -1，
因此出場目標 **77.6233 bp**。到目標的價差空間由回零的 128.2051 bp，變成 50.5818 bp。

保留相同現行成本／時間公式、相同當時輸入，只切換 absolute 目標替換，重新算出的數值：

| 項目 | 回零 absolute | 以 Q 目標替換 absolute |
|---|---:|---:|
| 評估目標（bp） | 0 | 77.6233 |
| 當日到達機率 | 30.9524% | 29.2081% |
| 後續交易日到達機率 | 67.5170% | 69.4104% |
| 未到目標、至到期機率 | 1.5306% | 1.3816% |
| EV（bp） | 83.6385 | 6.8434 |
| 預估持有（日曆日） | 2.8734 | 2.7108 |
| 此路線 score（bp／日曆日） | 29.1082 | 2.5244 |

此例進場滑價 11.9 bp、出場滑價 3 bp。到正值目標就平倉的淨收益，
當日只有 `128.2051 − 11.9 − 77.6233 − 3 − 20 = 15.6818 bp`；
隔夜為 **1.6818 bp**，所以重新加權後的 EV 明顯較低。

改完後最高分其實換成 settle 路線：EV 79.3051 bp、持有 16.1319 日、
score **4.9161**，仍低於 A 門檻 **5.8219**，所以整筆拒絕。
原回零篩選則是 **29.1082 > 5.8219**，可以進場，實際仍採 max-Q 出場。

舊版這筆事後記錄獲利 **750 元**。上述比較證明篩選選擇改了，不能單靠這點把 750 元判為假獲利。
若回零 EV 本來就是你的篩選指標，後續允許 max-Q 提早獲利，改動後就是另一套策略；
若你要 EV 表示真正出場方案的預期收益，才需要將評估目標對齊，但仍需另做預測校準。
本次依要求解釋及補報表，沒有再次改動策略。

### 1.4 原版到現行還有哪些 EV 計算差異

前次報告中，68.11%／72.77% 的獲利落差占比只隔離「正值目標替換」。原版到現行另外包含：

| 其他改動 | 精確內容 |
|---|---|
| 持有時間 | 結算終點由到期後下一交易日改為到期日；隔日及更晚的預估時間補入當天剩餘日數。 |
| 到期分支成本 | residual 未達目標的結算分支補入結算成本；當天到期適用 20 bp，同日以外用 34 bp。 |
| S2 滑價下限 | 進場估計至少含半個現貨 tick 的成本下限，原本未套用。 |
| 評分快取 | 原本將價差／anchor 四捨五入並按分鐘共用；現行依商品與完整精確輸入重用，避免套錯分數。 |
| 輸入有效性 | 排除過大的 scale、無效 anchor；無可用 residual 時仍允許 absolute／settle 評估。 |

所以原始封存公式在此例是 EV 83.6385、T 2.7976、score 29.8963；
本文純目標比較使用現行共同時間公式，是 T 2.8734、score 29.1082。
舊報告「只在封存公式改目標」的 EV 6.8848／score 2.6165，也不同於本文完整現行公式的 6.8434／2.5244。
這些數字有不同控制條件，不能混成同一組對照。
完整程式差異保存於 `evaluation_20260929/ev.diff`、`policy.diff`；成本設定本身仍為同日／隔夜 20／34 bp。

## 2. 期末評估的統一口徑

期間 2026/1/26–8/13，共 131 個交易日，固定資本 20,000,000 元。

- **總交易數**：完成現貨／期貨進場配對的筆數；一組 pair 算一筆，不把各腿成交或撤單重掛當成新交易。
- **已平倉／未平倉／rollback**：分開列示。進場未完成就回補的 rollback 不列入完成配對筆數，但其損益納入總淨損益。
- **平均單筆損益**：主要看已平倉配對的 `pnl_net` 平均，已扣費用。另列「總淨損益／完成進場配對」，該值含 rollback 與期末評價，不能冒充已實現單筆平均。
- **獲利單／虧損單**：只取已平倉配對，分別平均正／負淨損益；勝率也是相同母體。
- **資金使用**：列每日收盤占用的平均、最高值及除以 20M 的使用率；這是 131 個收盤觀測的平均，並非盤中或全日時間加權平均。另列經稽核的盤中峰值、收盤部位筆數與期末占用。
- **持有時間**：從 `hedge_ns`（兩腿完成進場配對）到兩腿平倉且待處理任務結束的 `close_ns`；舊版用其記錄的 `exit_hedge_ns`。以 24 小時為一個日曆日，含夜間、週末和假日，不含等待進場成交的掛單時間。
- **未平倉帳齡**：配對完成到 8/13 13:20 的經過時間，另外呈現，不當作已結束的持有時間混入平均。
- **年化**：`含期末評價的總淨損益 / 131 × 250 / 20M × 100%`。回零對照各兩筆、原點位各九筆期末評價均只加入一次。

原點位匯出將 `open_marked` 的 state 寫為 closed，本報告依 `close_kind` 還原為未平倉，避免灌入已平倉統計。
原點位數字屬歷史紀錄的統計重建，不新增對其執行正確性的背書；盤中稽核峰值留空，沒有拿收盤峰值冒充。
