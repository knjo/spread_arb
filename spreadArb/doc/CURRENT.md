## 研究基準的下單與部位

1. 未成交單不占部位。已占 1,980 萬時，可掛合計 500 萬，但每張名目不得超過當時剩餘 20 萬。
   部分／完整成交立即計入占用；額度變少立即送撤不再符合額度的進場單。
2. 只按實際發生的進出更新。現在占滿 2,000 萬，即使稍後將平倉 500 萬，現在仍不能先接 500 萬。
   撤單需 50 ms；途中真實成交保留入帳，不為了守住上限刪除成交。兩腿及待處理單結束才釋放。
3. 同商品 S1、S2、E1、E2 各最多一張市場掛單，四路可並存。持有部位不限制筆數；
   仍受總資本 2,000 萬及原有商品金額上限 `max(單組名目，總資本 × 25%)` 限制。
   E1／E2 服務最早完成配對、已有 maker 出場目標且尚無出場成交的一筆部位，等待該筆目標達成；
   不跳過它改掛較新部位。同一路線的未完成 hedge／rollback 先處理完。
4. 一分鐘更新目前採「各張單生效後獨立計時 60 秒」的實作解讀。
   滿時送撤，50 ms 撤單生效後，進場以最新可見行情、EV、當日 hurdle 及剩餘額度重新判斷。
   出場重新檢查最早部位的目標價差，使用最新掛價；目標保持原進場決定的價差。
   不必等另一筆市場訊號才更新；不合條件就不重掛。部分成交先回補，不能因更新清掉真實曝險。

使用者原數字的合成時序測試已通過：先完成 99 筆各 20 萬的真實模擬成交與 hedge，
占用 1,980 萬，再掛 25 張各 20 萬（合計 500 萬），占用仍是 1,980 萬；20.1 萬新單被拒絕。
其中一張成交使占用達 2,000 萬後，其餘 24 張立刻送撤。
預排未來 500 萬平倉仍不能先接新單；直到那 500 萬的兩腿實際平倉才可重新掛 500 萬。
此情境用固定通過的 EV 隔離容量規則，並通過獨立帳務稽核；不是歷史績效抽樣。
完整時序在 `data/backtest/refresh_20260923_validation/user_capacity_scenarios.json`。
實際行情抽查亦有同時刻占用紀錄，例如 1/30 的 6285 先成交 1,000 股、183,000 元，
容量帳在該筆成交時間立即增加 183,000 元；詳見同目錄的 `actual_partial_examples.json`。
這些例子是局部證據；採用版 131 日逐事件稽核也已通過，必要容量撤單 A 6,277 次、B 4,269 次均已核對。

A hurdle 固定 8.5 bp／交易日，換算 5.8219178 bp／日曆日。
B 在前日收盤占用達 80% 時，取前日通過基礎門檻之獨立市場訊號 score 的 q50 與基礎門檻較大值。
計時重掛隨各組部位不同，不納入 B 的市場訊號母體；每筆實際送單的 EV 仍獨立重算驗證。
計時重評後的拒單也重新估算 EV，並核對各組當日 hurdle，避免只驗證有下單的情況。

## 執行與驗收

從 `futures_spot_spread/` 執行；每次選新的輸出名稱，勿同時啟動 A／B 兩份大回放。

```bash
export PYTHONDONTWRITEBYTECODE=1 UV_CACHE_DIR=/tmp/hft-uv-cache POLARS_MAX_THREADS=2
RUN="uv run --project /home/kevin/Project/HFT --no-sync python"
$RUN -m spreadArb.src.backtest.maintenance --receipt /tmp/spreadarb_cleanup_preview.json
# 清理預覽確認後，明確指定 --apply；不可在回放期間清快取。
$RUN -m spreadArb.src.backtest.maintenance --apply --receipt /tmp/spreadarb_cleanup.json
$RUN -m spreadArb.src.ev.build --start 20260126 --end 20260813 --force
$RUN -m unittest discover -s spreadArb/src/tests -t .
# 單獨執行採用的 B；未指定 --preset 也預設 B。
$RUN -m spreadArb.src.backtest.replay --preset B --out my_B --prefetch 0
$RUN -m spreadArb.src.backtest.causal_audit --run my_B --raw-all
$RUN -m spreadArb.src.backtest.ev_validation --run my_B
$RUN -m spreadArb.src.backtest.accepted_report --run my_B
```

中斷續跑用相同完整期間、名稱及 `--resume`；原始碼、設定或 Q 快取變動須新建回放。
驗收需要完整 131 日原始行情、成交量／深度、容量／現金／官方權益、掛單壽命與最新價格、全部送單及計時更新 EV；
測試通過或損益算術對上，單獨都不代表完成驗收。

保留的模型假設：同日／隔夜 20／34 bp 成本、無融資利息、到期 basis=0、公共 prints 的 FIFO／post-only 近似；
hedge 五檔足量才整筆執行，否則保留曝險等待重試。EV 算式正確不等於機率或持有時間已校準。

9/24 與本日選版前的歸因封存紀錄，保存的是當時程式／文件雜湊；它們不代表目前預設仍是實際目標 EV。採用後來源以 `selection_20260929/adoption.json` 為準。

需要 A／B 對照時，改用 `backtest.causal_replay --out my_AB --prefetch 0`，後續檢查與報告也改用 `my_AB`；兩種回放擇一執行。
